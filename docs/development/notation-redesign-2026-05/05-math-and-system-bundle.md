# 05. 数式記法 + system asset bundle architecture

## 5.1 motivation

PKC2 想定 user の中に数学 / 化学 / 物理 / 学術系がいる場合、数式表現は不可欠。superscript / subscript 等の native 機能で個別対応する代わりに、**業界標準 LaTeX/KaTeX 記法を採用**して math モード経由で全部解決する設計が整合的。

key decisions:

- LaTeX/KaTeX 記法を採用(GitHub / Obsidian / MyST / Quarto / Jupyter / Pandoc 全て採用、業界 de facto)
- KaTeX library + math fonts 完全 bundle(CDN 不可、offline 原則維持)
- これは PKC2 初の **system asset bundle**(binary asset を base64 inline で単一 HTML 内包)
- superscript / subscript は math モードに集約、native 機能としては削除

## 5.2 math 記法

### 5.2.1 inline math

```markdown
方程式 $x^2 + y^2 = z^2$ を考える。
```

→ `<span class="pkc-math-inline">…</span>` に KaTeX 展開、`x²+y²=z²`(数式 typesetting)

### 5.2.2 block math

```markdown
$$
\int_0^\infty e^{-x^2}\,dx = \frac{\sqrt{\pi}}{2}
$$
```

→ `<div class="pkc-math-block">…</div>` に KaTeX 展開、中央寄せ display 数式

### 5.2.3 LaTeX 互換 alternative

KaTeX は以下 syntax も accept(GitHub / MyST と同):

| inline | block |
|--------|-------|
| `$x$` | `$$x$$` |
| `\(x\)` | `\[x\]` |

PKC2 は `$...$` / `$$...$$` を canonical、`\(\)` `\[\]` も parse 受理(AI emit 友好)。

### 5.2.4 disambiguation rule(`$10` 通貨 vs math)

GitHub の rule に準拠:

| 入力 | 解釈 |
|------|------|
| `$x$` | math(`$` 直後 / 直前に non-space 文字)|
| `$10` | literal text(closing `$` が同一行内になければ math 起動せず)|
| `$ x $` | literal text(`$` 直後に space は math 起動せず)|
| `$10 と $20 を比較` | literal text(closing `$` までの間に space あり)|
| `あなたは $1000 払った` | literal text(同上)|
| `公式 $E=mc^2$ より` | math(`$` の前後 non-space)|

これで通貨記号と数式の一般的混在は安全に区別可能。

### 5.2.5 spec 仕様(KaTeX subset)

KaTeX が支援する commands は LaTeX のごく subset(数式関係)。PKC2 は KaTeX が parse できる範囲を全て support、それを超える LaTeX commands は warning + literal 残置。

代表的 commands(KaTeX docs 参照):

```
\frac{a}{b}            ← 分数
\sqrt{x}, \sqrt[3]{x}  ← 平方根、三乗根
\sum_{i=0}^{n}         ← 総和
\int_a^b f(x)\,dx      ← 積分
\lim_{x \to 0}         ← 極限
\matrix{a & b \\ c & d}← 行列
\alpha, \beta, \gamma  ← Greek
\mathbb{R}, \mathbb{Z} ← double-struck
\to, \rightarrow       ← 矢印
\le, \ge, \neq, \approx ← 比較・近似
```

## 5.3 KaTeX bundle 構成

### 5.3.1 内訳

| component | size | bundle 場所 |
|-----------|------|-----------|
| KaTeX core JS(minified)| ~280 KB | `bundle.js` |
| KaTeX CSS | ~25 KB | `bundle.css` |
| Math fonts subset(.woff2)| ~150 KB(必須 5 family、subset 化済) | **base64 → CSS `@font-face` data URI** で `bundle.css` に内包 |
| 計 | **~480 KB**(font は base64 化で +33%、CSS は実質 ~600 KB 増) | |

### 5.3.2 必須 font 5 family(subset)

KaTeX は 18 family を ship、PKC2 は 一般用途で必要な subset:

| family | 用途 | size |
|--------|------|------|
| KaTeX_Main-Regular | 通常 text 数式 | ~50 KB |
| KaTeX_Math-Italic | 変数(`x` `y`)| ~40 KB |
| KaTeX_Size1 | 大型 operator(`\sum` `\int` 等の自動拡大) | ~20 KB |
| KaTeX_AMS-Regular | AMS extension symbols(`\mathbb{R}` 等) | ~30 KB |
| KaTeX_Caligraphic-Regular | 筆記体(`\mathcal{X}` 等) | ~10 KB |

それ以外(Bold / Italic / SansSerif / Fraktur / Script / Size2-4 等)は subset から除外。これらが必要な数式は warning 表示 + Main-Regular で fallback render(視覚的劣化あり、ただし正しさは維持)。

完全 font 必要な user 向けに、将来 `flag: math.full_fonts = true` を設けて runtime 切替可能化を検討(Phase 後段)。

### 5.3.3 bundle 予算影響

| metric | 現状 | reform 後 |
|--------|------|-----------|
| bundle.js | 970 KB / 4608 KB(21%) | ~1250 KB / 4608 KB(27%、+280 KB) |
| bundle.css | 150 KB / 512 KB(29%) | ~750 KB / **1024 KB**(73%、+600 KB)← budget bump 必要 |
| dist/pkc2.html | 1.4 MB / 5 MB(28%) | ~2.1 MB / 5 MB(42%) |

**bundle.css budget を 512 KB → 1024 KB に bump** 必要、それ以外は healthy。

## 5.4 system asset bundle architecture(初の binary 内包機構)

PKC2 が math fonts を内包するのは初の **system asset bundle**(JS / CSS 以外の binary asset を HTML 内に embed する機構)。再利用可能な architecture として設計:

### 5.4.1 build pipeline

```
src/assets/fonts/katex/*.woff2          ← raw binary(checked-in or downloaded at build)
       ↓
   scripts/inline-fonts.cjs(NEW)         ← base64 encode + @font-face rule 生成
       ↓
src/styles/_katex-fonts.generated.css    ← @font-face section、source map 付与
       ↓
   vite build                            ← bundle.css に包含
       ↓
   build/release-builder.ts              ← bundle.css → dist/pkc2.html に inline
```

### 5.4.2 generated CSS 構造

```css
/* auto-generated by scripts/inline-fonts.cjs */
@font-face {
  font-family: 'KaTeX_Main';
  src: url(data:font/woff2;base64,d09GMgABAAAAAB...) format('woff2');
  font-weight: normal;
  font-style: normal;
}
@font-face {
  font-family: 'KaTeX_Math';
  src: url(data:font/woff2;base64,d09GMgABAAAAAB...) format('woff2');
  font-weight: normal;
  font-style: italic;
}
/* ... 5 family x 1 variant = 5 @font-face ... */
```

### 5.4.3 architecture pattern

将来 同 mechanism で再利用できるもの(候補のみ):

- **日本語表示フォント** subset(印刷品質保証、現状は OS default に依存)
- **icon font**(現状は unicode emoji + SVG inline で済み、当面不要)
- **数式以外の binary asset**(rare、需要待ち)

`scripts/inline-fonts.cjs` を generic な「woff2 → base64 @font-face」コンバータとして設計、新 font 追加は config 1 行追加で済む。

## 5.5 security

### 5.5.1 KaTeX 自体の trust

KaTeX には `trust` option:

```javascript
katex.render(src, el, { trust: false });   // PKC2 default
```

`trust: false` で以下 macro を無効化:

- `\href{url}{label}` ← 任意 URL を含めるリンク
- `\url{...}` ← 同上
- `\includegraphics{path}` ← 任意 path 画像
- `\htmlClass{...}` `\htmlId{...}` `\htmlData{...}` ← HTML attribute 注入

これにより数式中での XSS / link injection を構造的に阻止。

### 5.5.2 PKC2 layer の cap

| cap | default | rationale |
|-----|---------|-----------|
| 単一 math 式の文字数 | 4 KB | 異常に長い数式は誤入力 / 攻撃 |
| document 内 math 数 | 1000 個 | 多すぎる場合 render 過負荷 |
| KaTeX render timeout | 1 sec | parse loop 攻撃防御(KaTeX 自体に既定あり、PKC2 で再保証)|

超過は warning + literal 残置 + math モード抑止。

### 5.5.3 bundle integrity

build 時に `subresource integrity` 計算、build artifact への hash check で bundle 内容の改竄検知。これは KaTeX 含めた全 bundle に共通機構。

## 5.6 superscript / subscript の処理

### 5.6.1 削除する native 機能

reform 前に検討された:

- `^x^` (Pandoc superscript)
- `~x~` (Pandoc subscript)

これらは **PKC2 では採用しない**(superscript / subscript native 機能は削除)。理由:

- 用途のほぼ全部が math 関連、math モードで `$x^2$` `$H_2O$` で表現可能
- 一般文章での superscript(`1ˢᵗ`、`m²`)は unicode 文字直書きで対応可能(`㎡` 等)
- 商標(`™` `®`)は単体文字
- footnote markers は `[^id]` 別 feature(§04)
- `^^em-dot^^` を確保(視覚優先、頻度高)

### 5.6.2 formal でも提供しない

私の前回提案で `:sup:[x]` `:sub:[x]` formal を保留したが、math モードで全部 covered なので **formal も提供せず**(削除)。

ただし IR レベルでは `Sup{children}` `Sub{children}` は予約しておく(将来必要なら formal-only で復活可)。

## 5.7 footnote との関係(意図確認)

`^[text]` inline footnote(§04)と `^^em-dot^^`(§01.32)で `^` を 3 用途に活用:

| 記号 | 用途 | parser priority |
|------|------|----------------|
| `^^x^^` | em-dot wrap | 1(優先)|
| `^[x]` | inline footnote | 2(em-dot でない時) |
| `^x` | (採用せず、PKC2 では superscript native 削除) | — |

3 つ目の不採用により、`^[` と `^^` の 2-priority 設計で完全分離可能。

## 5.8 implementation outline

### 5.8.1 markdown-it plugin

`markdown-it-katex` (既存)を base、PKC2 spec に合わせて wrap:

- `$...$` / `$$...$$` 検出
- `$10` の disambiguation rule 適用
- KaTeX `trust: false` で render
- error 時は literal + warning(`pkc-math-error` class、`pkc-frontmatter-warning` 同型)

### 5.8.2 build script

`scripts/inline-fonts.cjs`(新規):

```javascript
// pseudocode
const fs = require('fs');
const fonts = [
  { name: 'KaTeX_Main',         file: 'KaTeX_Main-Regular.woff2',  weight: 'normal', style: 'normal' },
  { name: 'KaTeX_Math',         file: 'KaTeX_Math-Italic.woff2',   weight: 'normal', style: 'italic' },
  { name: 'KaTeX_Size1',        file: 'KaTeX_Size1-Regular.woff2', weight: 'normal', style: 'normal' },
  { name: 'KaTeX_AMS',          file: 'KaTeX_AMS-Regular.woff2',   weight: 'normal', style: 'normal' },
  { name: 'KaTeX_Caligraphic',  file: 'KaTeX_Caligraphic-Regular.woff2', weight: 'normal', style: 'normal' },
];
const css = fonts.map(f => {
  const buf = fs.readFileSync(`src/assets/fonts/katex/${f.file}`);
  const b64 = buf.toString('base64');
  return `@font-face {
  font-family: '${f.name}';
  src: url(data:font/woff2;base64,${b64}) format('woff2');
  font-weight: ${f.weight};
  font-style: ${f.style};
}`;
}).join('\n\n');
fs.writeFileSync('src/styles/_katex-fonts.generated.css', css);
```

### 5.8.3 6 surface 整合性

math は以下 surface で render される必要:

- center pane / Split View live preview / Split View edit-mode preview / Viewer popup / textlog log / 平文 fallback(該当なし)/ Rich copy
- 全 surface で同 KaTeX 経路、render 結果を `<span class="pkc-math-inline">` / `<div class="pkc-math-block">` に固定

## 5.9 設計まとめ + 確定事項

### 確定

- KaTeX library + math fonts 完全 bundle、CDN 一切使わず offline 維持
- inline `$...$` + block `$$...$$` の 2 形式
- `$10` 通貨 disambiguation は GitHub rule 準拠
- superscript / subscript native 機能は削除(math 経由で全部解決)
- system asset bundle architecture を初実装、将来 font / binary asset 追加に再利用可能
- bundle.css budget を 512 KB → 1024 KB に bump

### 議論待ち

- KaTeX font subset(必須 5 family)が user 用途に十分か?
- KaTeX 以外の math engine(MathJax / native MathML / typst)を選択すべき場合の判断基準は?
- AsciiMath alternative(`x^2` 直書き)を simple 形として併存させるべきか(私推奨:不要、math `$x^2$` で同等)
- 複雑な数式(物理 / 化学の専門記号)で KaTeX が unsupport な command の対処方針

## 5.10 レビュー観点

1. **KaTeX 採用判断**:de facto standard だが他選択肢(MathJax / native MathML)の優位性はないか?
2. **font subset 5 family**:漏れている用途(物理 / 化学 / 工学)はあるか?完全 font 提供 flag を初期から用意すべきか?
3. **bundle.css budget bump**:512 → 1024 KB は過剰 / 不足どちらに振れるか?
4. **`$10` disambiguation**:GitHub rule で edge case 漏れはないか?(`$ x $`、`$x $`、混在文書での誤判定リスク)
5. **superscript / subscript 削除**:user 想定が学術系に偏った時、削除判断が破綻しないか?
6. **system asset bundle architecture**:初実装としての設計、将来 font / binary 追加時に拡張容易か?
7. **6 surface での math render 整合**:全 surface で同 KaTeX 経路を使う運用、build asserter での verify 機構が必要か?
