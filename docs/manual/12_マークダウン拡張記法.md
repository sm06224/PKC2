# 12 マークダウン拡張記法

PKC2 は標準の CommonMark + GFM(table / strikethrough / task list) + linkify + typographer に加えて、**日本語文書 / 業務文書 / 通知文** で使いやすい拡張記法を独自に持っています。本章はその一覧と使い方ガイドです。

> **本章のステータス**(2026-05-08 時点):
>
> - **Phase 1(L-1〜L-9)は安定実装済**。本マニュアルに記載の構文は今後も維持されます(後方互換が保証)。
> - **Phase 2 以降の追加が今後も予定されています**(track changes / 変数 / 用語集 / スプレッドシート埋め込み等)。新規 markup が増えるとこの章も追記されます。最新の構文一覧は本章 / `docs/development/markdown-dialect-extensions-spec-2026-05.md`(設計議論)/ `docs/spec/markdown-dialect-for-ai-authors-v1.md`(AI 向け規約書)を確認してください。

## 12.1 早見表

| ID | 名称 | 構文 | 用途 |
|----|------|------|------|
| L-1 | セクション区切り | `+++` または `+++ {role=section}` | 章の改ページ / 強い区切り |
| L-2-a | ハイライト | `==text==` | 黄色マーカー強調 |
| L-2-b | 振り仮名(ルビ) | `[[ruby:漢字\|かんじ]]` | 漢字の読み方を上に |
| L-2-c | 圏点(けんてん) | `[[em:重要]]` | 各文字の上に「・」を付ける日本語強調 |
| L-3 | 引用 | `> text` | CommonMark 標準 |
| L-4-a | コメント(行内) | `%% メモ %%` | render 時に完全削除されるメモ |
| L-4-b | コメント(複数行) | `%%%\n...\n%%%` | ブロックコメント |
| L-5 | 行頭アライン | `\|\|` `\|>` `<\|` | 段落を中央 / 右 / 左寄せ |
| L-6 | 簡易インライン | `:文字:bold,red,lg:` | 色 / 太字 / サイズ等の組合せ |
| L-7-a | 図 / 表 / 式ブロック | `:::figure{#id}\n...\n^^^ caption\n:::` | 自動採番付き図表 |
| L-7-b | 図 / 表 / 式参照 | `[@id]` | 「図 1 を参照」のような本文中リンク |
| L-8 | 空行マーカー | `_` または `_<N>` | 縦余白の明示(N 行ぶん) |
| L-9 | 段落字下げ | `__` または `＿`(全角) | 段落先頭 1 字下げ(日本語慣習) |

**全ての行頭マーカー**は **行頭の半角スペース / TAB / 全角スペース(U+3000)を無視** します。`   |>` も `\t__段落` も `　_3` も全部正しく認識されます。

## 12.2 各 markup の詳細と例

### L-1 セクション区切り

```markdown
+++

+++ {role=section}
+++ {role=cover}
```

`+++` 単独行で改ページ / 区切り。`{role=...}` で意味付け:`section`(章) / `cover`(表紙) / `body`(通常) / `auto`(default)。Word / PPT export 時に role に応じてページ break や slide separator にマップされます(Phase 2 以降の export 機能で活きてきます)。

### L-2-a ハイライト

```markdown
本文中の ==重要== な事項。
```

`==` で囲んだ範囲が黄色マーカーになります。

### L-2-b 振り仮名(ルビ)

```markdown
[[ruby:漢字|かんじ]] を多用する文章で便利。
[[ruby:Tokyo|とうきょう]]
```

`[[ruby:本文|ふりがな]]` の形式。漢字以外でも英単語の発音表記などに。

### L-2-c 圏点(けんてん)

```markdown
[[em:重要]]事項
```

「圏点」は日本語特有の強調記号で、**各文字の上に「・」**を打って強調します。`<em>` の太字斜体とは別物の、文字単位の強調装飾。

### L-3 引用(CommonMark 標準)

```markdown
> 引用内容
> 複数行可
```

PKC2 独自挙動なし。CommonMark 標準のまま。

### L-4 コメント(render に出さないメモ)

```markdown
本文 %% この一文は再考、後で削除 %%

%%%
TODO: この section は仮置き。
最終版では削除する。
%%%
```

`%% ... %%` は同じ行内の inline コメント。`%%%` で囲んだ範囲は複数行のブロックコメント。**render すると完全に消えます**(CSS で hide ではなく出力自体に存在しません)。エクスポートしても残らないので、下書き段階のメモに最適。

### L-5 行頭アライン(段落寄せ)

```markdown
|| この段落はセンター寄せ。

|> この段落は右寄せ。

<| この段落は左寄せ(default なので明示は稀)。
```

行頭の `||` / `|>` / `<|` を置くと、その行から空行までの paragraph 全体が中央 / 右 / 左寄せになります。

**連続する別アライン行は別 paragraph として分離されます**(2026-05-07 確定挙動):

```markdown
|> 2026年5月8日

<| To: 関係者各位

|> From: 情報システム部
```

→ 3 個の独立 paragraph、それぞれ右 / 左 / 右寄せ。

### L-6 簡易インライン(色 / サイズ / 太字を組み合わせる)

```markdown
:重要:bold, red:
:大きく:lg, bg-yellow:
:120%サイズ:120%:
:総合:bold, italic, underline, red, bg-#fefce8:
```

`:文字:attrs:` の 3 区画で inline 装飾。attrs は半角カンマ区切り、複数併用可、順不同。

**vocabulary 一覧:**

| カテゴリ | 値 |
|--------|----|
| 強調 | `bold` / `italic` / `underline` / `strikethrough` / `code` |
| サイズ(段階式) | `xs` / `sm` / `md` / `lg` / `xl` / `2xl` / `3xl` |
| サイズ(自由値) | `120%` / `1.5em` / `0.75rem` / `12px` |
| 文字色 | CSS 色名 / `#hex` / `rgb(...)`(例 `red`、`#ff8800`)|
| 背景色 | `bg-<color>` / `bg-#hex`(例 `bg-yellow`、`bg-#000`) |
| font-family | `serif` / `sans` / `mono` |

**衝突回避**:`12:30:45` のような時刻表記は誤認識されません(`30` が attrs 語彙に当たらないため)。

### L-7 図 / 表 / 式 + 自動採番

```markdown
:::figure{#fig-architecture}
![](attachment:abc-image.png)
^^^ 全体構成
:::

本文 → 図 [@fig-architecture] を参照。
```

`:::figure{#id}` で開始、`:::` で閉じ、間の `^^^ caption` 行は省略可。`kind` を `figure` / `table` / `equation` のいずれかに切替可:`:::table{#tbl-1}` / `:::equation{#eq-1}`。

自動採番:同 entry 内の出現順で番号付与、caption に「図 1: ...」「表 1: ...」「式 1: ...」の prefix が自動付加されます。本文中で `[@fig-architecture]` と書くと「図 1」とリンク化されてクリックで対象に飛べます。

### L-8 空行マーカー(縦余白の明示)

```markdown
本文 1

_

本文 2(1 空行ぶん下)
```

```markdown
本文 1

_3

本文 2(3 空行ぶん下に大きく余白を取る)
```

`_` 単独行で 1 行ぶん、`_<N>`(N=1〜20)で N 行ぶんの余白。21 以上は 20 にクランプ。`_0` / `_3a` / `_word` 等は通常テキストとして残ります。CommonMark の連続空行 collapse 仕様で本文中に余白を制御できない問題を、明示マーカーで解決します。

### L-9 段落先頭 1 字下げ

```markdown
__段落本文。先頭の文字が 1 字下がります(日本語の段落字下げ慣習)。
__ 半角空白を挟んでも OK。
＿全角アンダースコアでも等価(U+FF3F)。
```

行頭 `__`(半角 `_` × 2)または `＿`(全角)で paragraph に 1 字下げ(`text-indent: 1em`)。

衝突回避:

- `___text___`(`_` 3 連続以上)は markdown horizontal rule なので字下げになりません
- `__bold__`(行末が `__` で閉じる)は markdown bold として処理、字下げになりません

**L-5 align prefix と併用可**:

```markdown
|| __センター + 字下げ
```

→ 中央寄せ + 字下げの両方適用。

## 12.3 行頭の空白系文字は無視されます

すべての行頭マーカー(L-1 / L-5 / L-8 / L-9)は、行頭の以下を **strip して** マーカー判定します:

- 半角スペース(任意の数)
- TAB(`\t`)
- 全角スペース(U+3000)

これにより、コピペでインデントが付いた状態でもマーカーが効きます。

## 12.4 Rich コピーで Word / ONLYOFFICE に貼る

PKC2 の **Rich コピー**(More メニュー → 🎨 Rich)を使うと、本文を inline `style="..."` 付きの HTML として clipboard に乗せます。Word / ONLYOFFICE / Gmail / Slack 等の rich-paste 先で:

- 中央寄せ / 字下げ段落 → そのまま中央 / 字下げ
- 黄色マーカー / 色付き太字 → そのまま色付きで貼り付き
- 圏点(text-emphasis)→ 対応 app では点が出る、未対応では plain `<em>` に graceful fallback
- 空行マーカー → Word の空段落として再現
- セクション区切り → 横線(`<hr>`)として再現

`docs/spec/markdown-dialect-for-ai-authors-v1.md` § 5(出力前 checklist)も併用すると、AI が生成した文書をそのまま Rich コピー → 業務 app に貼って体裁を整えるワークフローが実用的に回せます。

## 12.5 AI に PKC2 文書を書かせる(AI 規約書 v1 の活用)

AI(ChatGPT / Claude 等)に PKC2 の entry 本文を書かせるとき、**`docs/spec/markdown-dialect-for-ai-authors-v1.md`** を AI に prompt として渡すと、本章の markup を正しく使った文書を生成できます。

**典型ワークフロー:**

1. AI に `markdown-dialect-for-ai-authors-v1.md` の内容を貼り付け / 添付
2. 「以下の規約に従って PKC2 の markdown で〇〇を書いて」とお願い
3. 出力された markdown を PKC2 の text entry にペースト
4. 必要に応じて Rich コピーで Word / ONLYOFFICE に貼り付け
5. 体裁微調整のみで業務文書 / 通知文 / 報告書として使える状態になる

**AI 規約書 v1 の特徴:**

- self-contained(他 doc を参照しなくても規約だけで完結)
- 構文 / 衝突回避 / NG 例 / 出力前チェックリスト / 複合 fixture 例を 1 ファイルに集約
- マイナー追補は backward compat 必須(既存 markup の意味を変えない)
- メジャー破壊的変更は v2 として別ファイルに

**設計議論 / 業界事例 / IR 連動が知りたい方**は、別書 `docs/development/markdown-dialect-extensions-spec-2026-05.md`(human-oriented spec、~800 行)を参照してください。

## 12.6 Variables(`{{vars.x}}`、Phase 2 着地済 2026-05-08)

文書内変数。**frontmatter で定義した値を本文中で展開**できます。同じ文書を複数の宛先 / 用途で再利用するときに便利。

### 書き方

```markdown
---
vars:
  project: ALPHA-7
  client: Acme Corp
  date: 2026-05-08
  signature: 田中
---

# 案件 {{vars.project}} 進捗

本通知は {{vars.client}} 様向け、提出予定 {{vars.date}}。

|> 担当: {{vars.signature}}
```

→ render すると:

```
# 案件 ALPHA-7 進捗

本通知は Acme Corp 様向け、提出予定 2026-05-08。

                                                   担当: 田中
```

### 仕様

- `{{vars.<key>}}` で参照、`<key>` は英字始まり(`[A-Za-z_][\w-]*`)
- 内側空白は許容(`{{ vars.x }}` も OK)
- 改行を跨ぐ参照は無効(literal で残る)
- fenced code block(``` / ~~~)の中では展開しない
- inline backtick code span(`` ` `` ... `` ` ``)の中も展開される(2026-05-08 hotfix、`==xxx==` や `[[em:xxx]]` の中で展開できるようにするため)。literal にしたい場合は `\{{vars.x}}` で escape
- L-2 highlight / em-dot / ruby、L-6 simple-inline などの中身でも展開される
- escape は `\{{vars.x}}`(literal `{{vars.x}}` を出力)
- 未定義変数は **赤点線下線の警告**(`{{vars.unknown}}`)で残る → 気付いて修正できる
- `{{macros.x}}` / `{{export.x}}` 等 vars 以外の名前空間は Phase 2 では未対応(literal)

### AI 連携(宛先別 variant 生成)

ChatGPT / Claude 等に AI 規約書 v1 + 本節を流して、

> 「以下の vars だけ書き換えて、同じ本文を `経営層 / formal` 用と `現場 / casual` 用の 2 variant に分岐させて」

と指示すると、frontmatter の `vars` だけ差し替えた 2 つの entry を出力させられます。本文 1 つから複数の variant を AI prompting だけで生成できる、これが M-7 の主目的です。

## 12.7 Phase 2 以降の追加予定(今後拡張される領域)

- **Page layout**(M-5/M-6):用紙向き / 余白 / ヘッダー / フッター / ページ番号(Word / PPT export 連動)
- **Conditional content**(M-6、`:::if{format=...}`):宛先別の条件分岐
- **Backmatter**(M-1):奥付 / 索引 / 用語集 / 参考文献の構造化

- **CSV cell 型注釈**(M-3):Word/PPT export での書式直訳
- **暗黙ラベル**(M-4):heading path / term slug の自動 anchor
- **Track changes / suggest**(Phase 3、X):査読・添削モード
- **Spreadsheet entry**(領域 10-4、別 wave):新 archetype + cell 編集
- **format mapping マトリクス充実**:HTML / Word / PPT / PDF / LaTeX / ePub / Org / MD への mapping(領域 10-3 IR + 10-5 PKC-extension 連携が前提)
