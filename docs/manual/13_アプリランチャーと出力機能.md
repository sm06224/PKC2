# 13 アプリランチャーと出力機能(PR-2JJ v2)

PKC2 は単一 HTML ファイルなので、**他の単一 HTML ツール**(電卓、エディタ、独自ビューア等)を attachment として取り込んで、その HTML を新しいウィンドウで起動できます。本章では「アプリランチャー」「Data… メニュー(AST / Pandoc / Word / PPT / PDF 出力)」「編集中のフォーマットパネル」を説明します。

## 13.1 アプリランチャー

### 13.1.1 何ができるか

PKC2 にドラッグ&ドロップで取り込んだ **HTML attachment**(例:単一ファイル形式のミニツール)を、「アプリとして登録」しておくと、中央ペインの **Launcher view** にタイル形式で並びます。タイルをクリックすると、ブラウザの新規ウィンドウで HTML が起動します(既存の「🌐 Open in New Window」と完全に同じ挙動)。

### 13.1.2 アプリとして登録する

1. HTML ファイル(`.html`)を PKC2 のサイドバーや中央ペインにドラッグ&ドロップして取り込む
2. 取り込んだ attachment エントリを選択して、右ペイン(詳細表示)に出す
3. attachment カード内の「**🌐 Open in New Window**」ボタンの下に表示される **「アプリランチャーに登録」** チェックボックスを ON にする
4. 右隣の小さなテキスト欄に絵文字 1 文字を入力すると、その絵文字がタイルのアイコンになります(未入力なら default の 🌐)

これで登録完了。サイドバーの View 切替バー(Detail / Calendar / Kanban / Filer / **Launcher**)で「Launcher」をクリックすると、登録した HTML アプリの一覧が出ます。

### 13.1.3 タイル click で起動

タイルをクリックすると、HTML attachment の中身が新規ブラウザウィンドウで開かれます。元の PKC2 ウィンドウは変化しません。

### 13.1.4 URL から直接起動

URL に `?app=launcher` を付けて開くと、起動時に Launcher view が選択された状態になります(例:`pkc2.html?app=launcher`)。Bookmarklet / Home Screen アイコン経由で「いきなり Launcher を見せる」用途に使えます。

### 13.1.4b URL 起動タイル(2026-07 追加・オプトイン)

よく使う **Web サイトの URL** をランチャーのタイルにできます。Flags Inspector(右上 ⚙ → ⚑ Flags)で `shell.launcher_url_tiles` を ON にすると、Launcher のヘッダーに「**+ URL タイル**」ボタンが出ます。

- **追加**: ボタン → ジャンプ先 URL(http / https のみ)とタイル名を入力 → 🔗 タイルが並びます
- **中身**: タイルの実体は「中継ページ」を焼き込んだ小さな HTML 添付です。通常の添付と同じく **Export でそのまま持ち出せます**
- **referrer を送らないジャンプ**: タイルをクリックすると中継ページが開き、**referrer を一切送らずに**目的サイトへ自動遷移します(`no-referrer` + `rel="noreferrer noopener"`)。file:// 起動の PKC2 からのリンクを嫌うサイトや、参照元を渡したくない場合に有効です
- **削除**: 通常のエントリと同じく添付エントリを削除するだけです

### 13.1.4c ランチャーに並ぶもの(2026-07 更新)

Launcher には次の 3 種が並び、アイコンで見分けられます:

| 種類 | 既定アイコン | クリック時 |
|---|---|---|
| 登録アプリ(`アプリランチャーに登録` ON の HTML 添付) | 🌐 | 新規ウィンドウで起動 |
| **PKC-Extension**(「PKC-Extension として扱う」ON — 登録チェック不要で自動表示) | 🧩 | 拡張として起動(ホストと通信、§13.1.5) |
| URL タイル(§13.1.4b) | 🔗 | 中継ページ経由で URL へジャンプ |

### 13.1.4d タイルの整理 — 詳細導線・並び替え・グループ化(2026-07 追加)

**並び替えはドラッグ&ドロップ**です:

- タイルを **つかんで別のタイルの上に落とす**と、その **左半分なら前・右半分なら後ろ**に挿入されます(挿入位置はバーで表示)
- **別グループの領域(タイルの無い余白)に落とす**と、そのグループの末尾へ移動します
- 並びは保存され、次回起動後も維持されます

タイルに **マウスを載せる**(またはキーボードフォーカス)と右上に小さな操作ボタンが現れます:

| ボタン | 操作 |
|---|---|
| ⓘ | 元の **添付エントリの詳細画面** を開く(登録解除・アイコン変更・削除などはここから) |
| 🏷 | **グループ名を設定**。同じグループ名のタイルは見出し付きでまとまって表示されます。空欄で確定するとグループ解除 |

- グループを 1 つでも作ると、グループ未設定のタイルは「**(未分類)**」見出しの下に先頭表示されます
- 並び・グループは添付エントリ本体に保存されるため、**Export してもそのまま持ち出せます**

### 13.1.5 PKC-Extension — ホストと通信する拡張(2026-06 更新)

ただ別ウィンドウで開くだけのアプリと違い、**PKC-Extension** は起動後もホスト PKC2 とメッセージで通信し続ける拡張です(代表例: グラフ拡張 → [10 章 §10.2](10_filer_と_graph_と_inventory.md))。

**登録**: HTML attachment のカードにある「**PKC-Extension として扱う**」チェックを ON。「**スタートアップ起動**」を併せて ON にすると PKC2 起動時に自動で開きます(`?pkc-safe-mode=1` 付き起動でスキップ、ポップアップブロック時は右下にリトライボタン)。

**拡張が受け取れるもの(重要)**:

- 既定で届くのは **projection** = エントリの一覧・関係・統計の **メタ情報だけ**。本文・添付ファイルの中身は届きません
- 本文や添付の実体は、**あなたが「拡張へ送る」操作をしたときだけ**届きます(§13.1.6)。拡張側から勝手に取りに行く手段はありません

**サンドボックス実行(既定)**: 拡張は隔離された環境(sandbox iframe)で動きます。ホストの画面・保存データ・localStorage には構造的に触れず、通信は postMessage のみ。サンドボックス内の拡張は自身のデータを保存できない(再起動で状態を失う)点に注意してください。

**全権モード(trusted)**: 拡張が「同一オリジンでの全権実行」を宣言している場合、起動前に**確認ダイアログ**が出ます — 「🔒 サンドボックスで開く(推奨)/ 🔓 全権で開く / キャンセル」。全権で開くと、その拡張は PKC2 のコンテナ全体へ直接アクセスできるようになるため、**配布元を信頼できる場合のみ**許可してください。

### 13.1.6 拡張へ送る — 右クリック送付と既定送り先(2026-06 更新)

エントリや添付ファイルの実体を拡張に渡すには、**ホスト側からの送付操作**を使います:

1. **紐付け**: 拡張のカードにある「**「拡張へ送る」の宛先にする**」チェックを ON(拡張 entry の右クリック → 「🧩 拡張として紐付け」でも同じ)。紐付けた拡張が送付の宛先候補になります
2. **送付**: 任意のエントリを右クリック → 「🧩 拡張へ送る」→ 宛先を選ぶ。**添付ファイルならカードの「🧩 ○○で開く」ボタン**からワンクリックでも送れます(例: docx を docx ビューア拡張で開く)。拡張が閉じていれば自動で起動してから届きます
3. **既定送り先**: 送付メニューの「📌 ○○を既定にして送る」を押すと、その種類(添付なら MIME、他は archetype)の既定宛先として記憶され、以後は ★ 付きで先頭に出ます
4. **確認・取消**: ヘッダー右上 ⚙ メニューの **Extensions** セクションに、紐付け済み拡張と既定送り先が一覧されます。「解除」「✕」でいつでも取り消せます(「PKC-Extension として扱う」を OFF にした場合も紐付けは自動解除)

> 送るという操作そのものが「この実体をこの拡張に渡してよい」という同意です。確認ダイアログは出ません(全権モードの起動時を除く)。

### 13.1.7 構成を拡張へ送る — AI 整理プラン連携(2026-07 追加)

エントリ / フォルダの**ツリー構成**を拡張へ渡し、AI を載せた拡張に**整理プランを提案させる**ことができます。[05 日常操作](05_日常操作.md) の「構成コマンド(AI 整理プラン)」のコピー & ペースト往復を、拡張チャネル経由でコピペレスにしたものです。

1. **送付**: コマンドパレットから「**構成を拡張へ送る(AI 整理プラン連携)**」を実行します。宛先は「開いている紐付け済み拡張 → 紐付けが 1 件だけならそれ」の順で決まります(曖昧な場合は送らず、案内が出ます)
2. **提案の受け取り**: 拡張が整理プラン(構成コマンド列)を返すと、**確認モーダルが「🧩 ○○からの提案」として自動で開きます**。dry-run プレビューで適用内容を確認し、「適用」を押して初めて反映されます
3. **拡張へ返る結果**: 適用した / 適用せず閉じた、のどちらだったかが拡張側に通知されます

**安全設計**: 拡張の提案がデータを直接変更することはありません(適用は必ずあなたがモーダルで確認)。渡る構成情報はタイトルと階層だけで、**本文は含まれません**。読み取り専用コンテナへの提案は自動で拒否されます。提案の受付は同時 1 件で、確認中に届いた後続の提案は拒否されます(表示中の内容が勝手に書き換わることはありません)。

## 13.2 Data… メニュー — AST / Pandoc / Word / PPT / PDF 出力

PKC2 のヘッダー右上にある「**Data…**」ボタンをクリックすると、エクスポート / インポートと並んで以下の出力オプションが現れます(現在 select されているエントリが対象):

### 13.2.1 AST / Canonical / Pandoc / HTML(クリップボード copy)

| ボタン | 出力内容 | 用途 |
|--------|----------|------|
| 🧬 AST | AstDocument JSON | AI に markdown を構造化データで渡したいとき |
| 🧬 Canonical | 正規化された AstDocument JSON | diff 比較 / round-trip テスト |
| 🧬 Pandoc | Pandoc Native JSON | `pandoc --from json` で各種形式に変換 |
| 🧬 HTML | render 済 HTML 文字列 | ブラウザ以外の HTML レンダラに食わせる |

「**Pretty**」チェックボックスを ON にすると整形 JSON、OFF(default)だと **JSONL = 1 行 compact** 形式で出力されます。AI / LLM 入力用は default の compact が便利です。

### 13.2.2 PDF / Word / PPT 出力

PKC2 v2.3.0 から、Word(`.docx`)と PowerPoint(`.pptx`)は **ブラウザ内で直接生成** されるようになりました(docx / pptxgenjs ライブラリを bundle 内蔵)。Pandoc を別途インストールする必要はなく、ボタン 1 つでローカル PC に保存できます。

| ボタン | 動作 | 出力ファイル |
|--------|------|------------|
| 📄 PDF | 印刷可能な viewer popup を開く。popup 内で「印刷」 or `Ctrl+P` を押して「PDF として保存」を選択 | (印刷ダイアログ経由) |
| 📝 Word | docx ライブラリでブラウザ内 docx 生成、即座にダウンロード | `<title>.docx` |
| 🎞 PPT | pptxgenjs ライブラリでブラウザ内 pptx 生成、即座にダウンロード | `<title>.pptx` |

#### Word 出力で何が再現されるか(v2.3.0 Wave Z)

v2.3.0 の Wave Z(W11〜W24)で Word / PowerPoint 出力の品位が大きく前進しました。

**dense web layout doctrine**:line-height 1.0(11pt 固定)+ 本文フォント 10.5pt + 余白 2cm 統一 + 見出し階段 16/14/12/10.5pt が default 適用されます。Word のデフォルト(line-height 1.15 + 段落間に 8pt 隙間)では業務文書として隙間が空きすぎる、という反省を反映したパラメータです。

**段組組版**:frontmatter で `layout: a4-2col` のように指定すると、A4 縦の 2 段組レポート体裁になります。`a4-1col` / `a4-2col` / `a4-3col` / `b5-1col` / `b5-2col` / `letter-1col` / `letter-2col` / `legal-1col` / `legal-2col` の 9 種が用意されています。

**箇条書きの bullet を小型化**:従来の Word デフォルトでは巨大な `•` U+2022 が使われていましたが、PKC2 は中点 `·` U+00B7 + hanging 240 twip(タイトめのぶら下げ)に切り替えました。リスト項目間の視覚的密度が読みやすくなります。

**表の cell padding 詰め + autofit**:cell padding を 60 twip(約 3pt、1mm)に詰め、`TableLayoutType.AUTOFIT` で列幅を内容に応じて自動調整します。Word default の「全 cell 同サイズ + 大きい padding」を撤廃。

**脚注 native**:`[^id]` 参照 + `[^id]: 本文` 定義が、Word の **`FootnoteReferenceRun` + `Document.footnotes` API** で **真の脚注機能** に変換されます。ページ下部に番号付きで表示され、Outline View / 印刷出力でも参照リンクが機能します。

**図表 caption 自動採番**:`:::figure{#fig-x}` + `^^^ キャプション` が「図 1: キャプション」のように自動採番されます。表 / 式の場合は `kind=table` / `kind=equation` で「表 N」「式 N」に切り替わります。本文中で `[@fig-x]` と参照すると「図 1」に展開されます。

**引用の著者表記**:`:::quote{author="Knuth" year=1974 source="Computing Surveys"}` のように attrs を指定すると、引用本文の後に italic + 右寄せで「— Knuth, 1974, Computing Surveys」が自動付与されます。

**callout box(8 role)**:`:::section{role=warning}` などの role 別 callout box が、Word でも shading + accent border + icon の組み合わせで色付きの情報ブロックになります。

**数式の視覚区別**:`$x^2 + y^2 = z^2$` のような数式が Word で Cambria Math フォント + italic で render されます。block 数式(`$$X$$`)は中央寄せで displayed equation 体裁になります。

**振り仮名(ふりがな)**:`[[ruby:漢字|かんじ]]` が「漢字 + 上付き小文字のかんじ」の 2 run 形で出力されます。Word の本物のルビ機能は docx ライブラリ未対応のため近似ですが、印刷時の furigana 効果は得られます。

#### PowerPoint 出力で何が再現されるか

Word とほぼ同等の機能セットを PowerPoint でも実現しています。

- 扉スライド / 本文スライド / 表中心スライドの 3 種類のスライドマスター
- `PKC_SECTION_SLIDE` / `PKC_CONTENT_SLIDE` / `PKC_TABLE_SLIDE` の正式 placeholder で、Outline View / accessibility tree がタイトルを認識します
- スライド番号 + Chapter 番号の running footer
- callout box(role 別 icon + 色)
- 引用 author attribution
- 図表 caption auto-numbering
- 数式 / 上下付き / ふりがな(近似)
- 段組(`a4-2col` 等)はスライド内の縦割り split で再現

#### 試してみる ── 1 つのレポートが 4 surface で書き出される

frontmatter に `layout: a4-2col` を書いた TEXT entry を 1 つ用意して、本文に図表 + 脚注 + 引用 + callout を含めて書きます:

```markdown
---
title: Q2 進捗報告
author: 佐藤太郎
layout: a4-2col
vars:
  product: "PKC2"
  quarter: "Q2"
---

# {{vars.product}} {{vars.quarter}} 進捗

## 要約

==[red]Critical:== セキュリティパッチ適用が完了[^patch]。

[^patch]: CVE-2026-XXXX の対応。

:::section{role=tip}
品質指標は前 quarter から大幅改善。
:::

:::figure{#fig-progress}
| 指標 | Q1 | Q2 |
|------|----|----|
| Test | 7100 | 8067 |
:::

詳細は [@fig-progress] を参照。

:::quote{author="Knuth" year=1974}
Premature optimization is the root of all evil.
:::
```

この同じ markdown から:

1. PKC2 中央ペインで HTML プレビュー(リアルタイム)
2. 📝 Word ボタンで A4 2 段組の docx
3. 🎞 PPT ボタンで対応する pptx(扉スライド + 本文スライド)
4. 📄 PDF ボタンで印刷可能な viewer

の **4 surface すべて** が得られます。同じ意味の文書が、HTML 表示 / Word 配布 / 発表資料 / 印刷物として一度に手に入る、というのが PKC2 v2.3.0 の到達点です。

## 13.3 MD コピーボタンの 2 種類

TEXT エントリの **More…** メニュー(action bar 右下)に、Markdown copy が 3 つ並びます:

| ボタン | 出力 |
|--------|------|
| 📋 MD | **GFM 標準**にクリーンアップした markdown(PKC 拡張 marker を剥がす)。**相互運用先 = Word / Notion / Obsidian / GitHub 等** |
| 📋 PKC MD | **正規記法 PKC MD**(AST 経由 + canonicalize 適用)。**用途 = PKC ↔ PKC round-trip / spec 準拠** |
| 🎨 Rich | Markdown + HTML を同時 clipboard 書き込み(リッチエディタに貼り付け可能) |

例:`==red text==` が含まれる本文を copy した場合 — GFM では `<mark>red text</mark>` に変換、PKC MD では `==red text==` のまま canonical 形に。

## 13.4 編集中のフォーマットパネル

TEXT entry の編集モード(本文 textarea)で文字を選択すると、選択範囲の上にフォーマットボタンの **フローティングツールバー**(B / I / S / ` / == / .. / sup / sub / link / H1 / H2 / H3 / > / · など)が出ます。ボタンを押すと選択範囲が PKC MD 記法で wrap / prefix されます。

### 13.4.1 各ボタンの動作

| ボタン | PKC MD 出力 |
|--------|-------------|
| B | `**選択範囲**`(strong) |
| I | `*選択範囲*`(emphasis) |
| S | `~~選択範囲~~`(strike) |
| \` | `` `選択範囲` ``(inline code) |
| == | `==選択範囲==`(mark) |
| .. | `..選択範囲..`(em-dot 強調点) |
| sup / sub | `<sup>…</sup>` / `<sub>…</sub>` |
| link | `[選択範囲](url)`(`url` は後で書き換え) |
| H1 / H2 / H3 | 行頭に `# ` / `## ` / `### ` を付与 |
| > | 各行頭に `> `(quote) |
| · | 各行頭に `- `(bullet list) |

### 13.4.2 パネルの ON / OFF

- 一時的に閉じたい場合 → パネル右端の **✕** ボタンで session 中の hide(reload で復活)
- 完全に表示しない場合 → ヘッダー右上 ⚙ → Flags Inspector → `editor.format_panel_enabled` を OFF にする(Tier 0 flag、default ON)

## 13.5 TEXTLOG のログ単位 Data…

TEXTLOG エントリの各ログを **右クリック** すると context menu が出ます。「🧬 Log data」section に以下 5 項目が並びます:

- 📋 MD (GFM) — このログを GFM 標準で copy
- 📋 PKC MD — canonical PKC MD で copy
- 🧬 AST — このログの AstDocument JSON
- 🧬 Pandoc — Pandoc Native JSON
- 🧬 HTML — render 済 HTML

TEXT entry の Data… メニューと同等を **ログ単位** で実行できます。「特定の 1 ログだけ Word に出したい」「LLM の input にこの 1 ログだけ与えたい」といった用途に便利です。

## 13.6 一般的なワークフロー例

### 13.6.1 「他人の Word / Notion に貼り付ける用に綺麗にしたい」

1. TEXT entry を選択
2. More… → **📋 MD**(GFM cleanup)を押す
3. 貼り付け先で paste — PKC 拡張(`==marker==` / `:::section` 等)が GFM 互換に変換されている

### 13.6.2 「AI に AST で食わせたい」

1. TEXT entry を選択
2. Data… → **🧬 AST**(default JSONL compact)を押す
3. ChatGPT / Claude / Gemini のチャットに paste

### 13.6.3 「Word に出力したい」

1. TEXT entry を選択
2. Data… → **📝 Word** を押す → `<title>.docx` が**ブラウザ内で直接生成**されてダウンロードされます(v2.3.0 から Pandoc のインストールは不要)

### 13.6.4 「PDF に出力したい」

1. TEXT / TEXTLOG entry を選択
2. Data… → **📄 PDF** を押す → 新規ウィンドウで印刷可能 viewer が開く
3. `Ctrl+P` / 「印刷」ボタン → 「**PDF として保存**」を選択

### 13.6.5 「自作のミニツール HTML を PKC2 から開けるようにしたい」

1. ミニツール HTML を PKC2 にドラッグ&ドロップ
2. 取り込んだ attachment を選択
3. 右ペインの「アプリランチャーに登録」を ON
4. View 切替で **Launcher** タブを開く → タイルから起動

## 13.7 開発者向け補足(API)

PKC2 は `window.PKC.ast` namespace に以下の関数を公開しています(`?pkc-debug=ast` を付けるとブラウザ DevTools console で叩けます):

```ts
PKC.ast.parseMarkdown(text)        // → AstDocument
PKC.ast.canonicalize(ast)          // → AstDocument(idempotent)
PKC.ast.renderHtml(ast)            // → string(HTML)
PKC.ast.renderMarkdown(ast, opts)  // → string(GFM or PKC MD)
PKC.ast.toPandocJson(ast)          // → Pandoc Native JSON
PKC.ast.markdownToPandoc(text)     // 1 step convenience
PKC.ast.version                    // '1.1.0'
```

詳細は `docs/spec/public-ast-api-for-ai.md` を参照。
