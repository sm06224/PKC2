# 外部 AI への相談 ── プロンプトを作って user に仲介してもらう

> **「構造的に無理」と結論しかけたら、それは外に聞く合図である。**
> 自分の知識の外側は、考えても出てこない。**捏ねる時間を、聞く 1 往復に replace する。**

user 指示(2026-07-29):
> 「今回のあなたは**自分の中で答えを求めすぎてがんじがらめになっている**。
> そういう時は**最新技術に明るい gemini とかに頼るのは良い手**だと思います」

---

## 0. なぜ要るか ── 実際にやらかした形

2026-07-29、mermaid の SVG を canvas へラスタ化しようとして
`The canvas has been tainted by cross-origin data.` で失敗した。
そこで **`<foreignObject>` を含む SVG は描けない = 構造的に無理**と結論し、
「設計の作り直しが要る」と doc に書いて push した。

**誤りだった。** 試したのは **Blob URL の 1 経路だけ**で、
**Data URL では通る**(foreignObject を含んだまま、ラベルの文字ごと描ける)。
user 経由で外部 AI の指摘をもらって初めて気づいた。

🔴 **失敗の構造**: 1 経路で転んで、**ブラウザのセキュリティモデルの制約**という
**一般則に飛躍**した。自分の外側にある知識(「Data URL なら通る」)は、
どれだけ考えても出てこない。

---

## 1. 🔴 使う合図(自分で気づくためのリスト)

次のどれかが出たら、**手を止めて本スキルを使う**。

- 「**構造的に無理**」「**仕様上できない**」「**モデルの制約**」と結論しかけている
- 環境由来のエラー(`Failed to execute ...` / `SecurityError` / `NotSupportedError`)を
  **回避策なしで**受け入れようとしている
- **同じ 1 経路**を書き方だけ変えて 3 回以上試している
- ライブラリ / ブラウザの**既定の挙動**が想定と違い、設定名が分からない
- 「知らない」と「存在しない」を区別できていない
- 2026 年以降の API・ライブラリ挙動に関する判断で、**知識のカットオフを跨いでいる**

⚠ 逆に**使ってはいけない**場面:
- **この製品でどうすべきか**の判断(方針 / 優先度 / 見た目の取捨)
  ── それは user 裁定であり、外部 AI の領分ではない
- リポジトリ内を読めば分かること(先に `pkc2-surveyor` / grep)
- 測れば分かること(先に `perf-measurement`)

---

## 2. 送る前に ── **変数を 1 つずつ変えたか**

外に聞く前に 30 秒でこれを確認する。**聞かずに済むことがある**し、
聞くにしても「何は試したか」が書けないと良い答えは返ってこない。

- 失敗した経路の**変数を列挙**した?(URL 方式 / エンコード / 要素の有無 / 設定値)
- そのうち**実際に変えて試したのは何個**?
- 1 個しか変えていないなら、**それは「無理」の根拠にならない**

> mermaid の件では変数が 2 つ(URL 方式 × foreignObject の有無)あり、
> **1 つしか動かしていなかった**。

---

## 3. 仲介を依頼するプロンプトの作り方

**user が第三者サービスに貼る**ものである。以下を守る。

### 入れるもの

1. **1 行の問い** ── 何が知りたいか。「動きません」ではなく
   「〈環境〉で〈操作〉をすると〈エラー文〉になる。回避策はあるか」
2. **エラー文を逐語で**(要約しない。検索性がここに全部ある)
3. **試した経路と結果の表** ── 「何を変えて、どうなったか」。
   ここが最も答えの質を上げる
4. **制約** ── 本製品の事情のうち**答えを絞るのに必要なものだけ**
   (例:「単一 HTML 製品なので重い依存は足せない」「見た目は変えたくない」)
5. **欲しい答えの形** ── 「回避策の候補と、それぞれの副作用」など

### 入れないもの(user が外部に貼る前提を忘れない)

- 🔴 **秘密**(token / 鍵 / 内部ホスト名 / 未公開の個人情報)
- リポジトリの**大量のソース**。再現に要る**最小の断片**だけ
- 社内固有の名前で、**答えに関係しないもの**
- user の個人的な文脈

### 雛形

```
【環境】
Chromium <version 相当> / <ライブラリ名 と version> / <ブラウザ or Node>

【やりたいこと】
<1 文>

【起きていること】
<エラー文を逐語で>

【試した経路と結果】
| 変えた変数 | 結果 |
|---|---|
| A | 〜 |
| B | 〜 |

【制約】
- <答えを絞るのに必要なものだけ>

【欲しい答え】
- 回避策の候補と、それぞれの副作用(見た目 / 依存 / 対応ブラウザ)
- 「できない」なら、その根拠(仕様のどこか)
```

---

## 4. 提示の作法

- **会話文で提示する**(`AskUserQuestion` は使わない ── CLAUDE.md 会話・提示ルール)
- プロンプトは**そのままコピペできる 1 ブロック**にする。前置きを混ぜない
- 「これを Gemini 等に貼っていただけますか」と**依頼を明示**する
- 待っている間、**その答えに依存しない作業を進める**。止まらない
- 答えが来なくても進める道(既定 OFF で置く / 別案)を 1 つ用意しておく

---

## 5. 🔴 持ち帰った答えは **採用ではなく検証から入る**

外部の答えは**仮説**である。そのまま実装しない。

1. **変数を 1 つずつ変える実験に落とす**(A/B ではなく A/B/C)
   > mermaid の件: (a) Blob+FO あり / (b) **Data**+FO あり / (c) Data+FO 除去
   > の 3 腕。これで「原因は URL 方式であって foreignObject ではない」が確定した
2. **「落ちなかった」を成功と呼ばない**。中身が正しいことを別の指標で見る
   > 例外が出ないのに白紙、が最悪。**画素差で「ラベルが描けている」を確認**した
   > (foreignObject あり版と除去版の差 2.58%)
3. **外部の答えが触れていない事実を探す**。答えは「手段」を教えるだけで、
   「この製品で得か」は教えてくれない
   > mermaid の件: ラスタ化は**通った**が、測ったら **DOM は −98.5% なのに
   > メモリは減らない**(blink_gc −1.5MB / cc +4.5MB)。
   > **手段の成立と、採用の是非は別**だった
4. 自分の以前の結論を**訂正であることを明示して**撤回する。消さない

## 6. 実例(2026-07-29、そのまま雛形として使える)

送ったもの:

```
【環境】Chromium / mermaid v11 / ブラウザ内 JS
【やりたいこと】描画済み mermaid SVG を canvas でラスタ化して PNG にしたい
【起きていること】
  Failed to execute 'getImageData' on 'CanvasRenderingContext2D':
  The canvas has been tainted by cross-origin data.
【試した経路と結果】
  | Blob URL + <img> + drawImage | 上記エラー |
【制約】単一 HTML 製品なので重い依存は足せない。図の見た目は変えたくない
【欲しい答え】回避策の候補と副作用
```

返ってきた要点:
- 原因は `<foreignObject>`
- 回避 1: `htmlLabels: false`(**Data URL を使うこと**)
- 回避 2: html-to-image / resvg-wasm(依存が増える)

**検証で分かったこと**(= 返答をそのまま採らなかったから分かったこと):
- 原因は `<foreignObject>` **ではなく Blob URL** だった。
  Data URL なら **foreignObject を含んだまま通る**
- ⇒ 回避 1 の `htmlLabels: false`(**見た目が変わる**)は**不要**だった
- ⇒ 回避 2 の依存追加も不要
- そして**メモリは減らない**(cc へ移る)という、返答が触れていない事実が出た

🔑 **返答は正しかったが、最良の道はその隣にあった。**
検証しなければ、見た目を変える必要のない変更で全 user の図を変えていた。

---

## やってはいけないこと

- 外部の答えを**そのまま実装する**(必ず 3 腕の実験に落とす)
- 「落ちなかった」で成功とする(中身を別指標で確かめる)
- **方針・優先度・見た目の取捨**を外部 AI に決めさせる(user 裁定)
- 秘密やソース全文を貼らせる
- 答えを待って**手を止める**
- 自分の誤った結論を**黙って書き換える**(訂正と明示して残す)
