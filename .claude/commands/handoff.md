`session-handoff` スキルの手順で、**引き継ぎ用の PR** を作る。

> **引き継ぎは PR を渡した時点で完成する**(user 指示 2026-07-26)。
> doc を書いただけ・会話に要約を書いただけでは完成していない。
> 次のセッションは会話履歴を持たないため、**1 個の URL に集約されている**ことが条件。

## 必ず入れるもの

1. 🔴 **最初の仕事の有無**(PR 本文の冒頭・3 択のどれか)
   - **あり** → 何を・どこから・完了条件。次セッションは確認せず着手してよい
   - **なし。指示待ち**
   - **なし。user 裁定待ちが N 件**(何を裁定してほしいか。**催促はしない**)

   ⚠ 曖昧にしない。「あとは適当に続けて」は次セッションに**勝手な仕事を作らせる**。
   「なし」と書くのは手抜きではなく、**それ自体が指示**。

2. **現在の状態**(main の HEAD / open PR / 予約 / 作業 branch)
3. **着地したもの**(PR 番号 + **実測値**)
4. 🔴 **やらないと決めたことと、その理由**(次セッションの再発明を防ぐ・最も価値が高い)
5. **未測定と「測って否定した」を分けて**書く
6. **user 裁定**(出典タグ付き = 不可侵)
7. **踏んだ罠は `.claude` へのポインタ**(PR で再説明しない)

## 手順

1. `git fetch --prune origin main` で状態を確定。**open PR / 予約を残さない**
   (残すなら引き継ぎ事項として明記する)
2. `docs/development/session-handoff-YYYY-MM-DD.md` を書き、同 commit で INDEX 登録
3. **引き継ぎ専用の PR** を出す(実装と混ぜない)。本文は**単体で読める**こと
4. user に PR URL を渡す ← ここで完成

最後にスキル §6 の自己点検を通す。
