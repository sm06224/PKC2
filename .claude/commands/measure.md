測る対象: $ARGUMENTS(未指定なら会話の文脈から 1 文で定義してから始める)

手順は `.claude/skills/perf-measurement/SKILL.md` に従ってください。
以下はその上に置くガードレールです。

- **問いを 1 文にできるまで測らない** ──「〈どの操作〉の〈どの指標〉が〈どの規模〉で
  〈どれだけ〉違うか」。書けないならここで止めて user に確認する
- **preflight**: `npm run build` と `npm run bench:fixtures:rev`(fixture は未 commit)
- **測る前に印字するもの**: 計器の応答確認(2 水準 + ノイズ床)/ fixture の各次元の件数。
  **0 の次元があれば、0 のまま測ってよい理由を言えること**
- **反復は同じコマンドを 3 回**叩いて手で並べる(どのハーネスも 1 起動では反復しない)
- **推定した機構は、それを切り分ける腕を足して直接観測してから**実装に進む。
  「たぶん〜だろう」で実装しない
- **doc 化**(`docs/development/<主題>-YYYY-MM-DD.md`)+ 同 commit で INDEX 登録。
  指標ごとの信頼度表と**限界の節**を必ず置く。
  仕上げは `merge-on-green` skill の手順で PR → merge まで

## やってはいけないこと

- 手法が固まる前に数字を会話に出す
- 「何もしない」を対照群と呼ぶ / 対照群の中に測定対象が紛れていないか確かめずに使う
- 差し引きで出た**倍率**を断定する(向きだけにする)
- `(program)` のような受け皿バケットを「バンドルのパース」等と断定する
- 百分率を「どの実行の、何に対する比率か」抜きで書く。改善後は取り直す
- 限界の節を省く
